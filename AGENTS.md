# Работа с Монетным Двором

## Исходник

- Рабочий источник игры: `index.html`. Эталон: `baseline/original.html`, его не менять.
- Обновление №4 описано в `docs/update-v4.md`: экономика из присланного файла, задания v2 внутри сохранения v1, `hires`, новые анимации. Не менять ключи хранения и не удалять старый прогресс. Награды фиксируются до визуальных эффектов.
- До правок читать `README.md`, относящиеся к задаче документы в `docs/`, затем актуальные функции в исходнике. Документация описывает снимок 2026-10-11; после правок источником истины становится текущий код.
- Исходный файл пользователя вне этой папки не является рабочей копией. Не перезаписывать его без соответствующего запроса.
- Не делать переписывание на фреймворк или разделение монолита попутно с небольшой правкой. Сначала сохранить поведение и покрыть изменяемые переходы.

## Инварианты

- `ECON` — чистые формулы. Сохранять маркеры `ECONOMY-START` и `ECONOMY-END`: инструменты читают этот блок из HTML.
- `world.coins` — актуальные монеты в сессии; `S.run.coins` обновляется при `serialize()`. Не считать его живой копией стола.
- `S.bars` — расходуемые слитки; `S.barsTotal` — пожизненный счётчик для бонуса. Покупка таланта не уменьшает `barsTotal`.
- Выплата за орла равна `roundNom(denom(tier) * valueMult())`, рассчитывается при приземлении. Офлайн использует отдельную модель без округления и временных бустов.
- `headsChance` — условная вероятность орла при отсутствии ребра. Не складывать её напрямую с вероятностью ребра.
- Престиж сбрасывает деньги и `run`, сохраняет остальные метасистемы. Изменение этого правила — изменение продукта.
- Не менять `SAVE_KEY`, формат или значение полей прогресса без явной миграции и проверки старого сохранения.
- Контент первого обновления: `ZONE_STORIES`, `COIN_LORE`, `HAT_SETS`, `JOURNEY`. Постоянные выдачи хранятся в `S.content`, достраиваются `ensureContent()`. Стабильные id нельзя переименовывать без миграции: это повторно откроет награду. Читать `docs/content-update.md`.
- Не доверять клиентским валютам, `initDataUnsafe`, признакам покупок и часам устройства при серверном учёте платных ценностей.
- Новые пользовательские строки вставлять как текст либо экранировать перед `innerHTML`.

## Проверки

- `node tools/analyze.cjs` проверяет синтаксис двух inline-скриптов и обновляет `verification/source-facts.json`.
- `node tools/browser-audit.cjs` требует Playwright и браузер, запускает игру в отдельных временных контекстах, блокирует внешние запросы. Личный профиль браузера не используется.
- `known-defect` — характеристика известной ошибки, не требование сохранять её. При исправлении заменить такую проверку на проверку корректного поведения и обновить `docs/findings.md`.
- Для затронутых механик проверить нормальный сценарий, граничный случай, сохранение и восстановление. Для интерфейса проверить 390×844 и 320×568, для Telegram отдельно настоящий WebView.
- Для правок заданий, найма, мержа и миграций выполнять `tools/update-v4-audit.cjs` после сборки Telegram.
- Для изменений адаптивности запускать `tools/responsive-audit.cjs`. Геометрия зависит от `#stage`, а не ширины всего приложения; соблюдать `F.left/right` и отступы Telegram.
- Перед выдачей Telegram-файла запускать `tools/build-telegram.cjs`, затем `tools/telegram-audit.cjs`. `telegram/index.html` генерируется из основной игры; вручную его не править. `STANDALONE:true` запрещает неподключённые серверные механики. Целевой бот — `coins_flipper_bot`, используется Main Mini App (`APP_SHORT_NAME` пустой). Репозиторий — `dzmitryizlobin/coinflipper`; `.github/workflows/pages.yml` собирает только `telegram/` для GitHub Pages.
- Документировать внесённое изменение, результат проверки и остающиеся ограничения. При сдвиге строк обновить карту.

## Публикация

- Инфраструктура и backend не входят в исходный HTML. `docs/state-and-api.md` различает существующий клиентский контракт и предлагаемую серверную реализацию.
- Демо-конфигурацию не считать production. Следовать `docs/release.md` и явному запросу пользователя на выпуск.
- Не помещать токен бота и серверные секреты в HTML, документацию, архив или клиентский конфиг.
- Публичный каталог должен содержать только игровые файлы; не публиковать весь исследовательский пакет с проверками и отчётами.
