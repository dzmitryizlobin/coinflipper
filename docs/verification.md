# Проверка текущей игры

Последний завершённый прогон: **51 из 51 сценария выполнены с ожидаемым результатом**. Из них 20 фиксируют обычное поведение, 9 проверяют новый контент и геометрию, 4 — исправления B03/B04/B12/B13, 12 воспроизводят оставшиеся известные проблемы, 6 проверяют экраны и их группы. Это не означает, что игра свободна от ошибок: для группы `known-defect` ожидаемый результат — наличие описанного дефекта.

Машинный протокол: [browser-results.json](../verification/browser-results.json). Браузер Chromium/Chrome 154.0.8037.99, Playwright 1.62.1. Дата проверки 11 октября 2026 года. Протокол содержит точное время UTC и значения каждого сценария.

Дополнительно обновление №4 проверено 9 сценариями `tools/update-v4-audit.cjs`, 15 сценариями адаптивности и `tools/telegram-audit.cjs`; протоколы в `verification/`. [Подробности](update-v4.md).

## Изоляция

Использован отдельный временный профиль и новый контекст на сценарий. Личный Chrome, аккаунт Telegram и настоящее сохранение пользователя не использовались. HTML отдавался через локальный перехват по `http://mint-dvor.test/`. Все внешние ресурсы и API подменялись пустыми ответами; Telegram SDK, шрифт и рекламная сеть не загружались.

В логических сценариях requestAnimationFrame отключён и `update` вызывается явно; случайность зафиксирована seed либо конкретным результатом. Поэтому можно точно воспроизвести редкие исходы и гонки. В снимках экрана работает обычный цикл отрисовки. Тестовый тап проходит через реальные события мыши canvas, большинство проверок механик вызывают функции напрямую с контролируемыми фикстурами.

## Новые сценарии

Проверены загрузка старого сохранения без `content`, сохранение прогресса и валют, запрет выдачи невыполненной или следующей вехи, запрет повторной выдачи после reload, прохождение всех 15 вех и сохранение отметок после престижа. Набор нельзя получить до сбора всех шляп; его выдача тоже переживает reload.

Кнопки «Цели», получения награды и перехода к ежедневным заданиям проверены через DOM. История монеты открыта с клавиатуры, для второго круга проверен дополнительный текст. Радиус равен удвоенному исходному во всех 30 проверенных зонах. На 390×844 и 320×568 проверены допустимые позиции двух стартовых и шести купленных монет, границы панели действий; drag merge проверен настоящими pointer-событиями.

Все 10 оформлений локаций отрисованы без необработанных ошибок. Дополнительно сняты цель, набор и история монеты на 320×568. Визуальные фикстуры и полное прохождение различаются: поздние экраны открываются искусственно подготовленным прогрессом.

Исходный протокол 40 сценариев сохранён в [baseline-browser-results.json](../verification/baseline-browser-results.json), исходная карта — в [baseline-source-facts.json](../verification/baseline-source-facts.json).

## Проверки дефектов

B01–B16 соответствуют [реестру проблем](findings.md). Для каждого сценария в протоколе есть значения, подтверждающие результат. B12 и B13 переведены в регрессионные проверки исправленного поведения. Два сценария относятся к потере офлайн-награды по разным причинам. Проверки платёжного replay и claim выполняют клиентскую функцию/подменённый ответ; настоящая серверная интеграция этим не сертифицируется.

## Адаптивность и сборка для Telegram

`tools/responsive-audit.cjs` выполнил 15/15 сценариев: 280×600, 320×400, 320×480, 320×568, 390×844, 430×932, 540×720, 568×320, 844×390, 768×1024, 1280×800, 1920×1080 и три варианта Telegram с safe areas или уменьшенной стабильной высотой. Каждая проверка включает старт, поздний прогресс, переключатель количества, настройки и четыре прокручиваемые панели. В Telegram-сценарии дополнительно проверены события изменения стабильной высоты, безопасных отступов и поворот того же окна. Протокол — [responsive-results.json](../verification/responsive-results.json).

`tools/telegram-audit.cjs` проверяет именно `telegram/index.html`: запуск, `ready`, отсутствие запросов к неподключённому серверу, отсутствие платных офферов и демо-выдач, базовую офлайн-награду и её сохранение, ссылку на заданное приложение. Протокол — [telegram-results.json](../verification/telegram-results.json). API Telegram имитируется; настоящее устройство и действующая ссылка запуска этим не проверяются.

Новая иконка настроек и переключатель визуально осмотрены в текущем окне приложения и в [мобильной фикстуре](../verification/responsive-mobile.png). Также просмотрены [горизонтальное окно](../verification/responsive-landscape.png), [настольное окно](../verification/responsive-desktop.png) и [отступы Telegram](../verification/responsive-telegram.png).

## Статическая проверка

`tools/analyze.cjs` компилирует оба inline-скрипта через Node VM без выполнения приложения, исполняет только чистый ECON для выгрузки таблиц и находит именованные объявления функций. Этот поиск функций не является полноценным AST call graph: анонимные обработчики и вызовы через объект не считаются отдельными именованными объявлениями.

Эталон `baseline/original.html` совпадает с первоначальной контрольной суммой. Рабочий `index.html` содержит контент и геометрические изменения; обе контрольные суммы находятся в `package-manifest.json`. `analyze.cjs` также извлекает актуальные каталоги контента.

## Повторный запуск

Из корня проекта при наличии Node.js:

```sh
node tools/analyze.cjs
```

Для браузерных сценариев установить зависимости в отдельной рабочей среде либо использовать уже имеющийся Playwright:

```sh
npm install --no-save playwright@1.62.1
npx playwright install chromium
node tools/browser-audit.cjs
```

При установленном Chrome можно вместо загрузки Chromium выполнить:

```sh
BROWSER_CHANNEL=chrome node tools/browser-audit.cjs
```

Результаты и снимки перезаписываются в `verification/`, образец defaultState — в `docs/save-default.json`. Скрипт не меняет игру. При отсутствии браузера следует явно сообщить об ограничении, а не считать проверки пройденными.

Для текущего компьютера Playwright доступен в комплекте среды Codex; повторный запуск возможен с NODE_PATH, указанным инструментом workspace dependencies. Абсолютный путь среды не встроен в переносимый проверочный сценарий.

Эти проверки относятся к выпуску и перечислены в [плане](release.md).
