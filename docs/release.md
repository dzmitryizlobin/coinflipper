# Подготовка игры к выпуску

Основная предполагаемая площадка — Telegram Mini App, поскольку под неё написан клиент. Состояние первой публикации GitHub Pages и подключения бота отражается в README. Для обычного сайта статическая часть уже пригодна к размещению, но покупки Stars, рефералы и облачные функции требуют соответствующего Telegram-контекста и сервера.

## Подготовленная сборка для пробного запуска

`node tools/build-telegram.cjs` создаёт каталог `telegram/` только с `index.html`. Он настроен для игры без сервера: `STANDALONE:true`, `DEMO_OUTSIDE_TG:false`, платные предложения и реклама отключены. Это позволяет загрузить игру на обычный HTTPS-хостинг и открыть в Mini App, не имитируя настоящую оплату. Известные неплатёжные дефекты клиента остаются в реестре, поэтому это сборка для пробного запуска.

Пользователь выбрал репозиторий `dzmitryizlobin/coinflipper` и бота `coins_flipper_bot`. Для него используется Main Mini App, пустой short name и сайт `https://dzmitryizlobin.github.io/coinflipper/`. Подготовлен workflow публикации из `main`. Подробности — [адаптивность и Telegram](responsive-telegram.md).

## Текущее состояние

| Часть | Что есть | Что необходимо для выпуска |
|---|---|---|
| Игра | Самодостаточный HTML, графика, звук, прогресс | Исправления воспроизведённых ошибок, проверка устройств |
| Хостинг | GitHub Pages, workflow из `main` | Первичная публикация подтверждена; отдельное тестовое окружение пока отсутствует |
| Бот | `coins_flipper_bot`, Main Mini App | Привязка HTTPS-сайта через BotFather |
| API | Клиентские запросы hello/invoice/claim | Реализация, доступная база и обработка ошибок |
| Покупки | Витрина и клиентская выдача | Серверная проверка платежа, журнал выдач, восстановление |
| Реклама | AdsGram adapter и демо | Реальный rewarded block, отключённая имитация в production |
| Сохранения | LocalStorage и части CloudStorage | Валидация, миграции, целостная запись, восстановление |
| Эксплуатация | Клиентские toast-сообщения | Сбор ошибок, резервные копии серверных данных, процедура отката |

## Этап 1 Стабильная игровая версия

Закрыть проблемы потери наград, повреждения прогресса и перекрывающихся объединений. Принять правило лимитов VIP. Добавить валидацию данных и миграции без смены ключа, приводящей к потере прогресса. Разделить production и demo. Сохранить эталон, актуализировать проверочные сценарии и выпустить первую версию с обозначенным номером.

До платной версии определить, какие ресурсы остаются локальными. Например, локальная симуляция анимации не обязана быть серверной, но платёжные права и повторяемые выдачи должны иметь устойчивый доверенный учёт. Полноценная серверная экономика — отдельный объём работ, её нельзя считать реализованной только из-за наличия Telegram CloudStorage.

## Этап 2 Тестовое окружение

Предлагаемая схема, отсутствующая в исходном файле:

```text
Telegram WebView → HTTPS static frontend
               → /api/hello, /api/invoice, /api/claim → backend → database
Telegram Bot API → webhook backend → orders, payments, entitlements, grants
Rewarded Ads SDK → verified completion path → reward transaction
```

Один origin для клиента и API проще для текущих относительных путей. На другом origin добавить ограниченный CORS для нужного frontend и заголовков. Выбрать хостинг под требуемую серверную среду после выбора реализации API; специфическую инфраструктуру этот разбор не навязывает.

Для тестирования использовать отдельного бота/данные/платёжное окружение и отдельный origin либо раздельное пространство сохранений. Не копировать пользовательские платёжные данные в тесты. Текущие тесты используют только созданные фикстуры.

## Этап 3 Конфигурация клиента

Перед встроенным скриптом приложения внедрить `window.APP_CONFIG` либо сформировать релизный HTML с параметрами:

```js
window.APP_CONFIG = {
  API_BASE: '',
  BOT_USERNAME: '<имя своего бота без @>',
  APP_SHORT_NAME: '<short name приложения>',
  ADSGRAM_BLOCK_ID: '<идентификатор rewarded блока>',
  ADSGRAM_DEBUG: false,
  DEMO_OUTSIDE_TG: false,
  SAVE_KEY: 'mintcoin_save_v1'
};
```

Этот пример не подключён к рабочему HTML и не содержит готовых реквизитов. До исправления B09 одного `DEMO_OUTSIDE_TG:false` недостаточно для полного контроля рекламной имитации. Секрет бота в клиент не включать. При изменении SAVE_KEY или origin подготовить перенос старого прогресса.

Telegram требует серверной проверки initData; запуск по ссылке использует bot username и app short name, а `startapp` передаётся как start_param. Проверить регистрацию ссылки и реальные safe areas в Mini App. [Telegram Mini Apps](https://core.telegram.org/bots/webapps).

## Этап 4 Покупки и награды

Реализовать каталог SKU, создание заказа, invoice link, получение webhook и устойчивую выдачу. Начислять только после серверного `successful_payment`, не по одному событию браузера. Telegram использует XTR для цифровых покупок, поддерживает тестовое окружение; бот должен обрабатывать `/paysupport`. [Оплата через Telegram Stars](https://core.telegram.org/bots/payments-stars).

На уровне приложения проверить:

- Повторный webhook и повторный claim не создают дополнительную выдачу.
- Закрытие игры после оплаты, но до применения grant, не теряет покупку.
- Смена устройства и аккаунта восстанавливает нужные права.
- Отмена, pending, failed, задержанный successful payment и возврат имеют понятный результат.
- Starter восстанавливает постоянную косметику, не размножая разовые валюты.
- Клуб явно реализован либо как 30-дневный доступ, либо как продлеваемая подписка; UI соответствует серверу.
- Реферал выдаётся один раз для допустимого нового пользователя.

Для AdsGram нужен rewarded block. В официальном SDK успешный promise rewarded означает досмотр; interstitial допускает закрытие и не должен подменять rewarded-сценарий. Обработать rejected promise и отсутствие рекламы, сохраняя основную офлайн-награду. [Интеграция AdsGram](https://docs.adsgram.ai/publisher/reward-interstitial-integration).

## Этап 5 Проверка кандидата

| Сценарий | Критерий |
|---|---|
| Новый игрок | Стартовые ресурсы, обучение, открытия и прогресс без ошибок |
| Игровые переходы | Все способы мержа, MAX, миньоны, переезд, престиж, сброс |
| Старый прогресс | Чтение сохранения предыдущей версии и корректная миграция |
| Офлайн | Не теряется и не повторяется при отказе, reload, crash и смене устройства |
| Облако | Неудачный chunk, таймаут, конфликт двух клиентов, неверные часы |
| Платежи | Тестовая покупка каждого SKU, дубли и восстановление |
| Реклама | Success, skip, fail, no-fill, дневной лимит, VIP |
| Экран | Android, iOS, desktop Telegram; 320×568, 390×844, короткий/горизонтальный viewport |
| Долгая сессия | Производительность, кеш, много монет/миньонов, многократный prestige |
| Поздняя экономика | Предел тиров, вместимость, конечность цен, точность больших чисел |

После соответствующих исправлений проверочный набор должен утверждать корректные инварианты. Нынешний успешный прогон подтверждает воспроизведение исходного поведения, включая ошибки.

## Этап 6 Публикация и откат

1. Собрать отдельный каталог релиза с игровым HTML и необходимыми ресурсами. Исследовательские документы, тесты и baseline туда не включать.
2. Сохранить release id, контрольную сумму, конфигурацию без секретов, совместимость версии сохранения и API. Сохранить предыдущий релиз.
3. Разместить на HTTPS, проверить content type и обновление HTML после выпуска; для этого файла предпочтительна ревалидация, чтобы клиент не оставался на старой версии.
4. Настроить ссылку Mini App, проверить из Telegram и выполнить smoke-сценарий. Реальные покупки включать после завершённого тестирования выдачи.
5. Контролировать ошибки запуска, успех загрузки/записи прогресса, платежи без выдачи, повторы выдачи и отказы рекламы. Схему аналитики и её события ещё предстоит реализовать.
6. При проблеме вернуть предыдущую клиентскую версию только если она совместима с уже записанной схемой. Иначе нужен подготовленный режим совместимости; откат кода не должен откатывать журнал реальных платежей.

Для фактического следующего шага понадобятся выбранный домен/хостинг, сведения о наличии backend, имя бота и short name, рекламный block id и решения по VIP/клубу. Разбор и локальные проверки от этих реквизитов не зависят.
